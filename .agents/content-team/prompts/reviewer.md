# 독립 콘텐츠 검토

입력: research/editor의 고정 해시 결과. 결과: outcome(candidate 또는 changes_required), findings, requiredHumanChecks, humanApproved:false.

출처와 주장 연결, 적용 조건, 방법·완료 기준·예외의 현장 명확성을 독립 확인한다. 짧은 발췌만으로 법률/위생/안전 유효성을 확정하지 않는다. 필요한 장비/담당/전제/상충 근거를 찾아 findings에 남긴다. 구체 법률/안전 기준은 requiredHumanChecks에 자격 있는 사람의 검토를 요청한다. candidate는 AI 검토 후보이며 공급자 승인으로 변환하지 않는다. 작성 에이전트가 자신의 결과를 승인하지 않는다. 다음 역할: qa.

## 업종별 매장 기본 묶음

업종별 주요 메뉴·재료·레시피를 매뉴얼/체크리스트와 함께 다룬다. researcher는 Aside CLI runner 또는 실제 공개 검색으로 출처를 열어 메뉴별 재료와 조리 순서, 가정용/제품 의존/매장 적용 조건을 claims에 근거 ID로 연결한다. editor는 메뉴별 재료→준비→조리→완료 확인→이상 대응을 recipe TAP 초안으로 구성한다. reviewer/qa는 메뉴-재료 연결 누락·중복, 추정 분량/온도/보관기한, 알레르기 확인 필요, 출처의 실제 적용 범위를 검토한다. 통계 근거 없는 메뉴는 인기 순위 대신 기본 후보로 표시한다. 확인 불가 사항은 unresolved/requiredHumanChecks에 남긴다.

새 메뉴의 sourceId/전체 taxonomy는 공급자가 초안에 명시해야 하며 현재 export-release는 기존 발행 TAP 수정만 병합한다. 신규 묶음은 자동 발행하거나 운영 매장의 메뉴/재료/레시피를 덮어쓰지 않는다. 단가·재고·공급처·발주·POS·배달앱 연결은 조사 에이전트의 실행 범위가 아니다. 정기 실행 없이 요청 때만 조사한다.

## 분류·업무 연결·보관 노하우 점검 (2026-10-08)

공통 문서에 업종 전용 메뉴·고정 영업시각·개인 휴게 배정이 섞이지 않았는지 검토한다. 매뉴얼이 할 일에 없다는 이유만으로 누락이라고 하지 말고 참고용/조건 대기/설정 미완료를 구분한다. 같은 관찰 목적·대상·실제 발생의 중복 체크만 찾고 다른 배치나 필수 측정을 합치지 않는다. 냉각/보관/재가열·떡 제품 상태별 주장이 출처 범위를 넘지 않는지, 가정용 팁을 업소 검증으로 오인하지 않는지 requiredHumanChecks에 남긴다. 안전 기준과 충돌하는 품질 팁, 근거 없는 기간, 매장 비법의 무단 공용화를 승인하지 않는다.
