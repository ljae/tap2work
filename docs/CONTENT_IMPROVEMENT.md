# 요청할 때마다 누적 개선하는 콘텐츠 팀

2026-10-07 구현. 사용자 선택은 **정기 실행 없이 직접 요청**이다. 자동 조사 예약은 해제했다. 별도 교육 기능은 없으며 매뉴얼·체크리스트에 집중한다.

## 개선 경로

요청 → 기존 출처/오류/평가 조회 → 공개 근거 조사 → 체크리스트/매뉴얼 편집 → 독립 검토 → QA → 초안 인계 → 제공자 검토/현장 피드백 → 다음 요청의 입력.

모델 자체의 가중치를 학습하거나 시간이 흐르면 정확도가 자동 상승하는 기능은 아니다. 조사 근거·실패·수정 이유를 지속 보존해 같은 실수를 줄이고, 개선 여부를 평가 가능한 기록으로 확인한다.

- `ContentMemory`: `.local/content-team/.learning/events/`에 추가만 가능한 사건을 저장한다. 기존 작업/출처/피드백을 다시 수집해도 중복 집계하지 않는다.
- 출처는 HTTPS 주소·기관·관할·적용 조건·발췌 해시·관측 작업/시점을 연결한다. 같은 문서의 여러 발췌도 보존한다.
- 출처 접속/본문 발췌 일치는 기술적으로 확인한다. 접속 성공은 사실 정확성이나 현재의 법적 유효성을 증명하지 않는다. PDF/과도하게 큰 문서/접근 제한은 미확인으로 남긴다.
- source 상태는 `candidate`, 제공자 평가의 `provider_checked`, 오류 신고의 `disputed`다. 재검색 횟수나 모델의 동의로 승격하지 않는다. 분쟁 상태는 반복 조사로 사라지지 않고 명시적 재확인 설명이 필요하다.
- 30일이 지난 관측, 접근 불가, 발췌 불일치, 오류 신고는 재확인 대상이다. 관찰 기간 기준은 출처 점검 우선순위이며 모든 근거의 유효 기간을 정한 정책이 아니다.
- 검토/QA/실행 실패와 제공자의 수정 이유를 다음 작업에 제공한다. 새 작업의 학습 입력과 공용 발행본은 고정해 중간 변경으로 결과가 섞이지 않는다.
- 미해결 관리 공백·부정 피드백·오래되거나 의심되는 관련 근거를 우선한다. AI가 제안한 다음 gap은 조사 후보이며 실제 매장 문제로 확정하지 않는다.

## 평가 기준

`correct/incorrect`는 제공자가 평가한 정확성, `helpful/not_helpful`은 실제 유용성 평가다. 같은 작업의 평가를 여러 번 입력해도 해당 지표는 한 작업의 마지막 평가만 집계한다. 출처를 실제 재확인한 경우 `revalidated`로 정정 이유를 남길 수 있다. `needs_changes`는 수정할 문제를 남긴다. 평가가 없으면 비율은 `null/미측정`이며 100%라고 표시하지 않는다.

제공자 피드백은 로컬 운영자가 정제해 입력하는 기록이다. Supabase 인증된 현장 피드백 UI나 독립 실험을 구현한 것은 아니다. 자유 입력의 모든 개인정보를 자동 제거하지 못하므로 사람/매장 식별 정보·비밀을 넣지 않는다. 현장 효과는 실제 적용 관찰을 남겼을 때만 평가한다.

## 직접 요청 실행

```sh
# 기본 모드는 manual/enabled:false. tick은 자동 실행하지 않는다.
npm run content:cycle -- status
# 미해결 후보 1건을 선택, 최신 DB 발행본 읽기, 최대 5역할 호출
npm run content:cycle -- run --request owner-request-20261007-01
# 동일 request ID 재실행은 완료 작업을 새로 실행하지 않는다.
```

서버 환경의 DB 키는 조율 프로세스의 **공용 발행본 읽기**에만 사용한다. Codex 역할은 서비스 키/운영 데이터 환경을 상속하지 않는다. 완료 결과는 로컬 `draft-request.json`과 provenance이며 실제 매장 내용/중앙 발행본에 자동 적용되지 않는다.

기존 미완료 작업이 있으면 새 요청에서 먼저 이어서 처리한다. 실패는 사라지지 않고 최대 3회 재시도/작업당 15회 한도와 이전 오류 안내를 적용한다. 요청당 모델 호출은 최대 5회이며 한도/시간이 토큰 비용의 정확한 상한이라는 의미는 아니다.

```sh
# 정제된 새 관리 공백 등록
npm run content:memory -- add-gap --file /path/to/gap.json
# {industry,gap,jurisdiction,sourceIds:[공용TAP sourceId],priority:0..100}

# 특정 실제 조사 작업에 대한 제공자/현장 평가
npm run content:memory -- feedback --file /path/to/feedback.json
# {eventId,jobId,verdict,reason,sourceUrls:[해당 작업의 출처주소],gapId:선택}

# 출처 관측·미측정 지표 확인
npm run content:memory -- status
npm run content:memory -- sources
# 한 번에 최대 10개 공개 주소를 확인, 기본 5개
npm run content:memory -- check-sources --limit 5
```

피드백의 eventId는 재시도에서 유지하고 내용이 바뀌면 새 ID를 부여한다. 확인하지 않은 출처를 `correct`로 입력하거나 fixture를 실제 조사로 집계하지 않는다. 예약을 해제하는 명령은 `content:cycle uninstall`이며 현재 launchd 등록이 제거된 상태다. 향후 사용자가 새로 요청할 때만 주기 설정/등록을 한다.

## 저장/실행 경계와 검증

현재 기억과 job은 이 개발 Mac의 로컬 저장소에 있다. 다른 작업 환경의 동일 팀과 자동 공유하는 클라우드 기억 저장소는 미구현이다. 로컬 files는 Git/공개 포털에 게시하지 않는다. 장기 자료는 source registry/이력으로 재사용하며 실제 콘텐츠는 기존 DB 검토·발행 경로로 넘어간다.

fixture 제외·중복 집계 방지·명시적 정정·분쟁 유지·오래된 근거·고정 입력·요청/재시작/한국 날짜 경계·사설 대상 차단·출처 변경/본문 일치·자동 발행 금지를 테스트했다. 별도의 교육·자동 코드 수정·사람 평가/채용 결정은 추가하지 않았다.

## 첫 실제 수동 조사

교대 인계의 누락/책임자/완료 기준에 대해 5역할을 실제 실행했다. 공개 출처4건, 검토·실패 메모12건, 조사후보6건을 기억에 누적했다. 웹2건은 접속/발췌 일치를 확인했고 PDF2건은 자동본문검증 미확인으로 남겼다. 연구자의 첫 열람시각 검증 실패 뒤 실제 실행시각/오류 안내를 전달해 재시도했고 역할 실행은 완료됐다. 검토/QA 보완으로 coordinator는 blocked, 검토용 DB 초안 export/운영 발행은 수행하지 않았다. 제공자/현장 평가가 없어 현재 정확성/유용성률은 null이다. 이를 다음 요청에서 고정된 과거 근거와 보완 사항으로 활용한다.
