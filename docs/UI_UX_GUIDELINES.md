## 3. 누구의 어떤 일을 돕는가

작은 식음료 매장의 사장님·매니저·크루가 바쁜 현장에서 짧게 확인하고 입력하는 상황을 기준으로 한다. 새 크루의 첫 근무 연습과 버디 확인을 유지하면서 업무·근무·재고·운영 설정을 연결한다.

화면 설계 전에 다음 네 가지를 한 문장씩 적는다.

- 사용자와 권한: 누가 조회·편집·승인하는가?
- 당장의 목적: 이 화면에서 끝내야 하는 일은 무엇인가?
- 저장 범위: 오늘 실행, 기본 양식, 선택 기간, 매장 공통 중 무엇이 바뀌는가?
- 완료 증거: 무엇을 보고 실제 저장·반영 여부를 알 수 있는가?

불필요한 설명은 줄이되 적용 범위·단위·권한·실패 원인은 생략하지 않는다. 빠른 입력을 위해 필수 항목을 먼저 두고, 관련된 세부 설정은 필요할 때 연다.

## 6. 폼과 바텀 시트

`showAppSheet`/`showAppFormSheet`, `AppEditorScaffold`, `AppFormSection`, `AppSheetFooter`, `AppSheetActions`를 우선 재사용한다.

- 제목은 한 번만 표시한다. 기본 정보 → 수량/시간 기준 → 연결 대상 → 상세 방법처럼 입력 판단 순서로 묶는다.
- 입력 라벨을 항상 보이게 하고 단위·선택 여부·허용 범위를 가까이 둔다. placeholder만으로 뜻을 전달하지 않는다.
- 선택은 공통 pill 계열 컴포넌트를 사용한다. 긴 목록은 검색·스크롤 가능한 선택 방식으로 연다.
- 주요 저장 버튼은 하단에 두고 SafeArea·키보드 높이를 반영한다. 마지막 필드가 footer에 가려지지 않아야 한다.
- 편집 중 바깥 탭·끌어내리기 닫기를 막더라도 명시적 닫기와 뒤로가기를 제공한다. 수정이 없으면 바로 닫고, 수정이 있으면 초안 처리만 확인한다.
- 초안 확인은 `계속 수정` / `변경 버리기`처럼 결과가 다른 두 행동을 구분한다. 닫기를 마케팅·알림 동의 유도로 바꾸지 않는다.
- 저장 중 중복 요청을 막는다. 실패하면 입력을 보존하고 재시도할 수 있게 한다. 충돌은 최신 값으로 조용히 덮어쓰지 않는다.

준비품 입력은 이름·단위, 준비 수량 기준, 업무 연결, 메뉴 사용량, 준비 방법을 구분한다. 영업시간은 휴무일 선택을 먼저 하고 영업일의 교대·시간·파트별 인원을 입력한다. 담당 파트 미선택은 `전체 파트 가능`임을 보여준다.

## 7. 직접 편집과 조작 범위

권한이 있는 항목을 길게 누르면 편집 모드로 들어가고 `편집 완료`로 종료한다. 이름·이동·삭제는 대상 가까이에서 제공한다. 길게 누르기와 드래그만을 유일한 조작법으로 두지 않고 이동 메뉴·명시적 입력 등 대안을 유지한다.

매뉴얼 왼쪽 구조 편집은 왼쪽만, 오른쪽 Task 편집은 오른쪽만 활성화한다. 왼쪽의 폴더/TAP/Task 아이콘·들여쓰기·펼치기를 유지하고 같은 사각형 카드로 평탄화하지 않는다. 편집 중 이름을 누르면 해당 ID의 이름 수정이 열린다. 빈 컨테이너에도 추가·이름·이동 등 가능한 행동을 제공한다.

업무의 수정 가능한 미완료 Task는 클릭해 직접 입력하고 마지막 Task 아래에서 추가한다. 현재 확정 범위는 선택한 오늘 미완료 실행과 기본 양식이며 완료 기록은 보존한다.

근무표의 드롭 예정 위치와 시작·종료 시각을 놓기 전에 보여준다. 높이 변경은 해당 배정의 시간 미세조정임을 명확히 한다. 반복 배정 재적용은 승인된 OFF·대체 배정·출퇴근·대기 신청이 있는 날짜를 보존하고, 나머지 날짜의 해당 반복 배정과 미세조정만 초기화한다. 별도 근무도 보존한다. 부분 OFF 신청은 쉬는 구간을 입력하며 승인 후 앞뒤 실제 근무로 나뉜다. 승인된 빈 구간에는 사장님이 같은 파트의 가능한 크루를 대체 배정한다. 공휴일 표시는 매장 휴무 설정과 구별한다.

## 8. 상태·권한·저장 피드백

| 상태 | 사용자에게 보여줄 것 |
|---|---|
| 최초 로딩 | 실제 화면 구조에 맞는 skeleton 또는 초기화 안내. 가짜 진행률·강제 대기 없음 |
| 빈 목록 | 무엇이 없는지와 권한에 맞는 다음 행동. 빈 폴더/TAP은 정상 상태 |
| 검색 결과 없음 | 검색 범위·검색어를 바꿀 수 있는 안내 |
| 읽기 전용/권한 없음 | 가능한 조회와 제한되는 편집을 구분. 성공처럼 보이는 저장 버튼 금지 |
| 저장 중 | 처리 중 표시와 중복 동작 방지. 입력·맥락 유지 |
| 저장 성공 | 서버 확인 뒤 완료 표시·목록 갱신. 저장되지 않은 초안과 구별 |
| 실패/충돌 | 문제와 다음 행동, 입력 보존. 반복 성공 알림이나 묵시적 덮어쓰기 금지 |
| 근무 변경 신청 | 신청 중에는 원래 근무 유지. 승인 후 반영 상태를 글자·표시로 구별 |

권한은 서버 판정을 따른다. 버튼 숨김만으로 권한 검사를 대신하지 않는다. 실제 발송·외부 연결·급여 이체가 없으면 완료했다고 표현하지 않는다. 공개 읽기 전용 체험과 인증 매장 저장을 혼동시키지 않는다.

## 9. 문구와 다국어 준비

직관적인 컨트롤은 짧은 라벨만 표시하고 반복 설명은 기본적으로 숨긴다. 부가 설명은 정보(ⓘ) 버튼으로 제공한다. 적용 범위·단위·오류·저장 상태는 필요한 위치에 유지한다. 설명은 짧고 쉬운 해요체로 쓰고 버튼은 동작이 드러나는 짧은 표현을 사용한다. 제한을 긍정적으로 꾸미다가 사실을 숨기지 않는다. 새 크루에게 압박·죄책감을 주는 표현은 피한다.

| 모호한 문구 | tap2work 문구 예시 |
|---|---|
| 확인 | 준비품 저장 / 이름 변경 / 근무 변경 신청 |
| 오류가 발생했습니다 | 저장하지 못했어요. 입력한 내용은 남아 있어요. 다시 시도해 주세요. |
| 처리 완료 | 변경을 신청했어요. 사장님이 승인하면 근무표에 반영돼요. |
| 선택 없음 | 전체 파트 가능 |
| 취소하시겠습니까? | 수정한 내용을 버릴까요? + 계속 수정 / 변경 버리기 |

오류 예시는 해당 원인과 실제 상태가 맞을 때만 쓴다. 간단한 조회 닫기와 삭제·변경 취소를 같은 버튼 문구로 취급하지 않는다.

현재 한국어 개발을 유지한다. [다국어 준비 계약](LOCALIZATION_PLAN.md)에 따라 상태는 코드·관계는 ID로 저장하고 번역 라벨로 로직을 판단하지 않는다. 긴 번역과 글자 확대를 수용하고 문장 조합을 피한다. 개인 언어가 매장 영업일·시간대를 바꾸지 않도록 한다. 사용자 작성 이름·매뉴얼을 임의 번역하지 않는다. 번역 UI·초대 발송은 이번 문서로 구현 완료 처리하지 않는다.

## 10. 모션·접근성·로딩 비용

공통 `app_motion.dart`를 사용하고 상태를 이해시키는 모션만 적용한다. 완료 효과는 저장 성공 뒤 한 번 재생하며 이를 위해 실제 완료를 늦추지 않는다. 동작 줄이기에서는 흔들림·shimmer·이동을 정지 표시나 즉시 상태 전환으로 바꾼다.

색만으로 승인·오류·선택을 전달하지 않는다. 아이콘 버튼에 의미 있는 접근성 이름을 주고 키보드 포커스·진입/복귀 위치를 확인한다. 확대 글자를 잘라내거나 강제 축소하지 않는다. 새 색 조합은 실제 글자 크기와 배경에서 대비를 확인하며 미검증 상태를 접근성 준수 완료라고 보고하지 않는다.

큰 장식·불필요한 애니메이션·과도한 이미지 변형을 추가하지 않는다. 첫 화면을 가로막는 불필요한 데이터 로딩과 중복 요청을 줄인다. 이미지 크기는 표시 용도에 맞추고 기존 데이터 갱신·캐시 계약을 재사용한다. 속도 개선은 측정한 로딩 구간과 조건을 함께 기록한다.
