# tap2work 맞춤 UI/UX 가이드라인

버전 1.0 · 2026-09-30 · 신규 화면과 기존 UI/UX 개선 시 **가장 먼저 읽는 디자인 기준**.

이 문서는 Toss 공식 문서의 복제본이나 TDS 적용 선언이 아니다. 외부 UX 원칙을 참고하되, tap2work에서 확정한 제품 흐름과 Flutter 공통 컴포넌트에 맞게 작성한 프로젝트 규칙이다. 문서 작성이 모든 기존 화면의 준수 완료를 뜻하지는 않는다.

## 1. 적용 순서와 문서의 역할

1. 현재 사용자 지시와 `project-state.json`의 최신 확정 결정을 확인한다. 과거 이력과 `proposed`를 현재 승인으로 취급하지 않는다.
2. 이 문서로 화면 목적, 흐름, 정보 위계, 입력과 피드백을 정한다.
3. [ARCHITECTURE.md](ARCHITECTURE.md)로 데이터·권한 경계를, [UI_SETTINGS_RELATIONSHIP_MAP.md](UI_SETTINGS_RELATIONSHIP_MAP.md)으로 진입 → 조작 → 저장 → 소비 화면을 확인한다.
4. [TOSS_UI_PROMPT_TEMPLATE.md](TOSS_UI_PROMPT_TEMPLATE.md)는 구현 요청용 요약으로 사용한다. [MOTION_GUIDE.md](MOTION_GUIDE.md)와 공통 코드로 세부 동작을 구현한다.
5. 지침과 실제 코드가 다르면 차이를 기록하고 해당 변경 범위에서 정리한다. 새로운 제품 선택은 확정 지시와 구현 제안을 구분한다.

디자인 규칙의 본문은 이 파일에서 유지한다. 수치의 구현 원본은 `design_tokens.dart`와 `design_system.dart`다. 수치를 바꾸면 이 문서와 요약 템플릿도 함께 갱신한다. 오래된 밝은 테마·메뉴명·편집 진입 정책을 다시 적용하지 않는다.

다음은 공식 페이지의 주제별 짧은 요약이다. 이후 절의 수치와 제품별 동작은 tap2work 자체 기준이다.

| 공식 가이드에서 확인한 주제 | 이 프로젝트의 적용 방향 |
|---|---|
| 브랜드 구분 | tap2work의 이름·로고·강조색을 일관되게 사용한다. |
| 사용자 선택을 방해하는 흐름 방지 | 진입·뒤로가기 중 불필요한 유도 화면을 끼우지 않는다. 버튼에서 다음 행동을 알 수 있게 한다. |
| UX 문구 | 쉬운 해요체와 명확한 행동 표현을 사용한다. 제한·오류는 정확하게 설명한다. |
| 그래픽 | 의미 있는 그림을 절제해서 사용한다. 상태를 오해시키는 장식은 피한다. |
| 해상도 | 논리적 크기와 이미지 밀도를 구분하고 대표 화면 크기에서 검증한다. |

원문의 미니앱 제출용 로고, 전용 내비게이션·탭바, 게임 전체 화면 규정은 현재 독립 Flutter 웹/앱의 의무 규칙으로 옮기지 않는다. 토스 그래픽에는 제휴 환경 사용 제한이 있으므로 현재 앱에 복사하지 않는다. 자체 로고·기존 라이선스 자산을 유지한다. 추후 토스 입점이 결정되면 당시 공식 규정을 다시 확인한다.

## 3. 누구의 어떤 일을 돕는가

작은 식음료 매장의 사장님·매니저·크루가 바쁜 현장에서 짧게 확인하고 입력하는 상황을 기준으로 한다. 새 크루의 첫 근무 연습과 버디 확인을 유지하면서 업무·근무·재고·운영 설정을 연결한다.

화면 설계 전에 다음 네 가지를 한 문장씩 적는다.

- 사용자와 권한: 누가 조회·편집·승인하는가?
- 당장의 목적: 이 화면에서 끝내야 하는 일은 무엇인가?
- 저장 범위: 오늘 실행, 기본 양식, 선택 기간, 매장 공통 중 무엇이 바뀌는가?
- 완료 증거: 무엇을 보고 실제 저장·반영 여부를 알 수 있는가?

불필요한 설명은 줄이되 적용 범위·단위·권한·실패 원인은 생략하지 않는다. 빠른 입력을 위해 필수 항목을 먼저 두고, 관련된 세부 설정은 필요할 때 연다.

## 4. 정보 구조와 탐색

| 위치 | 사용자가 기대하는 내용 | 유지할 경계 |
|---|---|---|
| 업무 | 오늘 실행할 TAP과 Task | TAP → Task → 매뉴얼. 파트는 분류이며 권한이 아니다. |
| 매뉴얼 | 폴더 → TAP → Task와 해당 방법 | 빈 폴더·빈 TAP 허용. 판매 메뉴 연결 이름은 매뉴얼 표시 이름만 수정한다. |
| 근무표 | 날짜·시간·파트·크루 배정 | 필요 인원, 계획 근무, 신청, 승인, 실제 출퇴근을 구별한다. |
| 우리매장 | 매장 공통 설정 | 다른 화면의 설정 진입점과 같은 편집 화면·저장 계약을 사용한다. |

네 주요 메뉴와 화면 제목을 일치시키고 공통 매뉴얼 검색 위치를 유지한다. 사람은 `크루`, 분류는 `파트`, 권한은 `직책`으로 쓴다. 내부 저장 키를 사용자에게 노출하지 않는다.

같은 설정을 다른 화면에서 열어도 항목·기본값·저장 효과가 같아야 한다. 예를 들어 우리매장 영업시간과 근무표 영업시간·인원은 같은 폼을 연다. 별도 복제 화면이나 중복 편집 버튼을 추가하지 않는다.

## 5. 시각 규칙과 정렬

아래 값은 Toss 공식 수치가 아닌 기존 tap2work 토큰과 공통 구현의 기준이다. Flutter logical px/sp를 사용한다.

| 항목 | 기준 |
|---|---|
| 서체 | 번들 Pretendard. 화면 제목 24/Bold, 섹션 18/Bold, 본문 16/Medium, 보조 13/Regular |
| 색 | 배경 `#101112`, 카드 `#181A1C`, 컨트롤 `#222528`, 본문 `#F0F2F4`, 보조 `#A0A7AF` |
| 강조 | 주요 버튼 `#007D73`, 초록 `#46C69B`, 코랄 `#FF9986`. 상태 의미 없이 색을 늘리지 않는다. |
| 여백 | 화면 좌우 24, 독립 섹션 32, 일반 관계 간격 8/16/24. 폼 섹션 안 입력 간격 20 |
| 카드 | 모서리 16–20, 공통 약한 그림자. 포커스·선택·드롭 대상은 구분 가능하게 표시 |
| 편집 시트 | 상단 모서리 28. `appEditorWidth=688`, 기본 좌우 24를 뺀 입력·footer 폭 640 |
| 주요 폼 동작 | 공통 시트 액션 최소 높이 56. 아이콘 동작의 터치 영역은 최소 48×48 확보 |

제목·필드·하단 버튼의 좌우 기준선을 맞춘다. 제목이 길면 줄바꿈하고 본문이 짧아도 위쪽에서 시작한다. 같은 줄의 동급 버튼은 같은 높이와 균형 잡힌 폭을 사용하며 좁은 화면에서는 세로로 배치한다.

글자를 줄여 화면에 우겨 넣지 않는다. 넓은 화면에서도 입력 폼은 읽기 폭을 제한한다. 근무표·트리는 내용에 필요한 열 폭과 내부 스크롤을 사용한다. 전체 화면 확대·축소로 폰과 데스크톱을 맞추지 않는다.

## 6. 폼과 바텀 시트

`showAppSheet`/`showAppFormSheet`, `AppEditorScaffold`, `AppFormSection`, `AppSheetFooter`, `AppSheetActions`를 우선 재사용한다.

- 제목은 한 번만 표시한다. 기본 정보 → 수량/시간 기준 → 연결 대상 → 상세 방법처럼 입력 판단 순서로 묶는다.
- 입력 라벨을 항상 보이게 하고 단위·선택 여부·허용 범위를 가까이 둔다. placeholder만으로 뜻을 전달하지 않는다.
- 선택은 공통 pill 계열 컴포넌트를 사용한다. 긴 목록은 검색·스크롤 가능한 선택 방식으로 연다.
- 주요 저장 버튼은 하단에 두고 SafeArea·키보드 높이를 반영한다. 마지막 필드가 footer에 가려지지 않아야 한다.
- 편집 중 바깥 탭·끌어내리기 닫기를 막더라도 명시적 닫기와 뒤로가기를 제공한다. 수정이 없으면 바로 닫고, 수정이 있으면 초안 처리만 확인한다.
- 초안 확인은 `계속 수정` / `변경 버리기`처럼 결과가 다른 두 행동을 구분한다. 닫기를 마케팅·알림 동의 유도로 바꾸지 않는다.
- 저장 중 중복 요청을 막는다. 실패하면 입력을 보존하고 재시도할 수 있게 한다. 충돌은 최신 값으로 조용히 덮어쓰지 않는다.

준비품 입력은 이름·단위, 준비 수량 기준, 업무 연결, 메뉴 사용량, 준비 방법을 구분한다. 영업시간은 휴무일 선택을 먼저 하고 영업일의 교대·시간·파트별 인원을 입력한다. 담당 파트 미선택은 `전체 파트 가능`임을 보여준다.

## 7. 직접 편집과 조작 범위

권한이 있는 항목을 길게 누르면 편집 모드로 들어가고 `편집 완료`로 종료한다. 이름·이동·삭제는 대상 가까이에서 제공한다. 길게 누르기와 드래그만을 유일한 조작법으로 두지 않고 이동 메뉴·명시적 입력 등 대안을 유지한다.

매뉴얼 왼쪽 구조 편집은 왼쪽만, 오른쪽 Task 편집은 오른쪽만 활성화한다. 왼쪽의 폴더/TAP/Task 아이콘·들여쓰기·펼치기를 유지하고 같은 사각형 카드로 평탄화하지 않는다. 편집 중 이름을 누르면 해당 ID의 이름 수정이 열린다. 빈 컨테이너에도 추가·이름·이동 등 가능한 행동을 제공한다.

업무의 수정 가능한 미완료 Task는 클릭해 직접 입력하고 마지막 Task 아래에서 추가한다. 현재 확정 범위는 선택한 오늘 미완료 실행과 기본 양식이며 완료 기록은 보존한다.

근무표의 드롭 예정 위치와 시작·종료 시각을 놓기 전에 보여준다. 높이 변경은 해당 배정의 시간 미세조정임을 명확히 한다. 반복 배정 재적용은 승인된 OFF·대체 배정·출퇴근·대기 신청이 있는 날짜를 보존하고, 나머지 날짜의 해당 반복 배정과 미세조정만 초기화한다. 별도 근무도 보존한다. 부분 OFF 신청은 쉬는 구간을 입력하며 승인 후 앞뒤 실제 근무로 나뉜다. 승인된 빈 구간에는 사장님이 같은 파트의 가능한 크루를 대체 배정한다. 공휴일 표시는 매장 휴무 설정과 구별한다.

## 8. 상태·권한·저장 피드백

| 상태 | 사용자에게 보여줄 것 |
|---|---|
| 최초 로딩 | 실제 화면 구조에 맞는 skeleton 또는 초기화 안내. 가짜 진행률·강제 대기 없음 |
| 빈 목록 | 무엇이 없는지와 권한에 맞는 다음 행동. 빈 폴더/TAP은 정상 상태 |
| 검색 결과 없음 | 검색 범위·검색어를 바꿀 수 있는 안내 |
| 읽기 전용/권한 없음 | 가능한 조회와 제한되는 편집을 구분. 성공처럼 보이는 저장 버튼 금지 |
| 저장 중 | 처리 중 표시와 중복 동작 방지. 입력·맥락 유지 |
| 저장 성공 | 서버 확인 뒤 완료 표시·목록 갱신. 저장되지 않은 초안과 구별 |
| 실패/충돌 | 문제와 다음 행동, 입력 보존. 반복 성공 알림이나 묵시적 덮어쓰기 금지 |
| 근무 변경 신청 | 신청 중에는 원래 근무 유지. 승인 후 반영 상태를 글자·표시로 구별 |

권한은 서버 판정을 따른다. 버튼 숨김만으로 권한 검사를 대신하지 않는다. 실제 발송·외부 연결·급여 이체가 없으면 완료했다고 표현하지 않는다. 공개 읽기 전용 체험과 인증 매장 저장을 혼동시키지 않는다.

## 9. 문구와 다국어 준비

직관적인 컨트롤은 짧은 라벨만 표시하고 반복 설명은 기본적으로 숨긴다. 부가 설명은 정보(ⓘ) 버튼으로 제공한다. 적용 범위·단위·오류·저장 상태는 필요한 위치에 유지한다. 설명은 짧고 쉬운 해요체로 쓰고 버튼은 동작이 드러나는 짧은 표현을 사용한다. 제한을 긍정적으로 꾸미다가 사실을 숨기지 않는다. 새 크루에게 압박·죄책감을 주는 표현은 피한다.

| 모호한 문구 | tap2work 문구 예시 |
|---|---|
| 확인 | 준비품 저장 / 이름 변경 / 근무 변경 신청 |
| 오류가 발생했습니다 | 저장하지 못했어요. 입력한 내용은 남아 있어요. 다시 시도해 주세요. |
| 처리 완료 | 변경을 신청했어요. 사장님이 승인하면 근무표에 반영돼요. |
| 선택 없음 | 전체 파트 가능 |
| 취소하시겠습니까? | 수정한 내용을 버릴까요? + 계속 수정 / 변경 버리기 |

오류 예시는 해당 원인과 실제 상태가 맞을 때만 쓴다. 간단한 조회 닫기와 삭제·변경 취소를 같은 버튼 문구로 취급하지 않는다.

현재 한국어 개발을 유지한다. [다국어 준비 계약](LOCALIZATION_PLAN.md)에 따라 상태는 코드·관계는 ID로 저장하고 번역 라벨로 로직을 판단하지 않는다. 긴 번역과 글자 확대를 수용하고 문장 조합을 피한다. 개인 언어가 매장 영업일·시간대를 바꾸지 않도록 한다. 사용자 작성 이름·매뉴얼을 임의 번역하지 않는다. 번역 UI·초대 발송은 이번 문서로 구현 완료 처리하지 않는다.

## 10. 모션·접근성·로딩 비용

공통 `app_motion.dart`를 사용하고 상태를 이해시키는 모션만 적용한다. 완료 효과는 저장 성공 뒤 한 번 재생하며 이를 위해 실제 완료를 늦추지 않는다. 동작 줄이기에서는 흔들림·shimmer·이동을 정지 표시나 즉시 상태 전환으로 바꾼다.

색만으로 승인·오류·선택을 전달하지 않는다. 아이콘 버튼에 의미 있는 접근성 이름을 주고 키보드 포커스·진입/복귀 위치를 확인한다. 확대 글자를 잘라내거나 강제 축소하지 않는다. 새 색 조합은 실제 글자 크기와 배경에서 대비를 확인하며 미검증 상태를 접근성 준수 완료라고 보고하지 않는다.

큰 장식·불필요한 애니메이션·과도한 이미지 변형을 추가하지 않는다. 첫 화면을 가로막는 불필요한 데이터 로딩과 중복 요청을 줄인다. 이미지 크기는 표시 용도에 맞추고 기존 데이터 갱신·캐시 계약을 재사용한다. 속도 개선은 측정한 로딩 구간과 조건을 함께 기록한다.

## 11. 작업·검수 체크리스트

아래는 새 변경의 검수 기준이며 앱 전체의 현재 통과 선언이 아니다.

- [ ] 화면 목적·편집 대상·저장 범위·권한이 분명하다.
- [ ] 네 메뉴·공통 검색·TAP/Task 구조와 문맥에 맞는다.
- [ ] 같은 설정의 진입점이 같은 폼과 저장 효과로 연결된다.
- [ ] 제목 중복, 버튼 크기 차이, 필드 기준선 어긋남, 과밀 배치가 없다.
- [ ] 320/390/1200px, 1.5배 글자, 긴 이름, 키보드, SafeArea를 확인했다.
- [ ] 빈 상태·로딩·실패·저장 성공·취소·권한 없음·충돌을 확인했다.
- [ ] 드래그 예정 위치, 이동 대안, 키보드 조작, 동작 줄이기를 확인했다.
- [ ] 실패 시 초안이 남고 저장 전 성공 효과가 나오지 않는다.
- [ ] 기존 완료·출퇴근·연결 ID를 유지한다.
- [ ] 변경된 컴포넌트·관계 문서·실제 검증 결과를 기록했다.

Flutter 변경은 분석과 관련 위젯 테스트를 수행한다. 설정 연결 변경은 관계표와 `npm run check:ui-links`, 서버 변경은 관련 서버 테스트와 `npm run test:console`를 적용한다. 시각 변경은 대표 크기의 캡처를 확인한다. 문서만 바꾼 경우 링크·수치·JSON을 검사하고 앱 테스트/배포를 했다고 기록하지 않는다. 웹 검증과 네이티브 실기기 검증도 구별한다.

### 공통 시간 입력과 주간 시간표 · D-064

영업시간·교대·근무 배정·OFF/단축의 시간 입력은 `AppTimeField`/`showTimeWheel`의 24시간 숫자 휠(시, 00/30분)과 명시적인 취소/적용을 재사용한다. 같은 의미의 입력에 시계형·임의 분 단위·별도 드롭다운을 새로 만들지 않는다. 요일별 시간표는 고정 시간축과 충분한 열 너비/가로 스크롤을 사용하고 시간대 겹침·빈 구간을 표시한다. 선택한 블록만 변경하며 드래그 중 적용 예정 시각을 보인다. 파트 분리는 기존 시간대 ID의 예외로 표시한다. 드래그가 어려운 경우 블록을 눌러 같은 숫자 휠로 수정한다. 영업일 경계 전 시각은 다음날 표시를 제공하며 실제 날짜와 업무 귀속 날짜를 구별한다.

### 영업시간 3단계 · 2026-10-03 최신 사용자 요청

휴무일 설정 → 교대 시간 분할 → 인원 배치의 고정 상단 탭을 사용한다. 다음 단계/일주일 설정 저장은 고정 footer에 둔다. 이전 세로 슬라이더를 가로 24시간 타임라인으로 대체한다. 1–3교대 선택은 즉시 분할하며 시작·종료·교대 구분선은 30분 단위 드래그와 숫자 휠을 함께 제공한다. 기본 교대명은 1교대 오픈, 2교대 오픈/마감, 3교대 오픈/미들/마감이다. 기존 이름은 명시적인 재분할 전 유지한다.

필요 인원은 교대 행 × 매장의 활성 파트 열(기본 주방·홀·관리)의 표로 표시한다. 셀을 눌러 0–12명을 조정한다. 작은 화면·확대 글자는 표 내부 가로 스크롤을 허용한다. 전체/개별 적용 범위와 요일 선택은 유지한다. 업무 연결·추가 시간대·파트 예외는 상세 설정 안에 보존한다. 기본 설명은 ⓘ로 제공한다.

영업일 경계 필드는 제거한다. 현재 단일 매장 경계 데이터 계약에 맞춰 일주일 영업일 중 가장 이른 영업 시작을 저장 경계로 사용한다. 모든 날 휴무면 이전 경계를 유지한다. 새 영업일 06:00–22:00, 브레이크 기본 15:00–17:00 및 ID·기록 보존은 유지한다.
