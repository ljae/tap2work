# 서비스 품질을 높이는 근무 흐름과 CS 매뉴얼 검토

검토일: 2026-10-14. 사용자 요구 중 **CS 매뉴얼을 포함한다**는 확정이다. 아래 제공 방식·우선순위·파일럿·자가 발전 스킬은 **proposed**다. 기존 앱을 일정/교육 전용으로 축소하거나 별도 LMS, 자동 조사, 자동 발행을 승인한 것으로 해석하지 않는다. 이번 작업은 조사·소스 감사·문서화이며 앱/운영 DB/공용 카탈로그 변경이나 배포가 아니다.

## 1. 권고하는 제품 방향

**TAP Work는 크루가 근무 전에 준비하고, 서비스 중 고객에게 집중하며, 다음 근무에 개선을 이어가도록 돕는 매장 운영 도구다.**

크루의 기본 사용 접점은 근무 시작·교대·마감이다. 사장님과 매니저는 근무표, 매뉴얼, 재고·발주, 미해결 업무를 관리한다. 서비스 중에는 필요한 순간에만 짧게 확인한다. 기존 업무·매뉴얼·근무표·우리매장 네 목적지와 첫 근무 연습/버디 확인을 유지한다.

성공 기준은 앱 체류 시간이나 체크 수가 아니라 고객 응대의 일관성, 인계 누락 감소, 크루의 판단 부담 감소다. 앱 열람을 실제 수행이나 고객 만족으로 간주하지 않는다. 인력 부족·품절·설비 고장·권한 부재를 교육 부족으로만 설명하지 않는다.

영상의 주요 논점은 말투, 거친 서빙 동작, 휴대폰으로 고객 신호를 놓침, 동시 응대로 주의가 분산됨, 마감 안내에서 불쾌감을 주는 행동이다. 약 3:40에는 휴대폰 사용 규칙, 5:04에는 응대 집중, 7:35에는 마감 안내를 다룬다. 약 14:41부터 작은 항목으로 시작해 실제 사건을 반영하며 매뉴얼을 늘리는 방향을 설명한다. 이는 운영자의 조언이며 재방문·매출 효과에 관한 대조 실험은 아니다. 영상의 휴대폰 일괄 반납이나 특정 브랜드 운영 방식은 이 앱의 확정 정책으로 옮기지 않는다.

## 3. 근무 라이프별 제공 방식

아래 시간은 신규 크루의 전체 교육이나 실제 오픈/마감 작업 시간이 아니라 짧은 앱 확인·브리핑의 파일럿 시작값이다.

| 시점 | 크루에게 필요한 것 | 제공 수단 | 앱의 역할 |
|---|---|---|---|
| 근무일 전 | 내 일정·변경·준비 사항 | 개인 휴대폰 | 근무표 확인과 필요한 신청. 의무 교육을 개인 휴게·비번 시간에 밀어내지 않음 |
| 첫 근무 | 장소·안전·역할·도움 요청·핵심 CS | 버디의 실제 시범, 짧은 매뉴얼 | 기존 첫 근무 안내를 유지. 읽음·따라 해봄·버디 확인은 구별 |
| 근무 시작 후, 고객 응대 투입 전 | 오늘 파트·버디·변경·품절·CS 한 가지 | 팀 브리핑 또는 공용 기기, 필요 시 개인 폰 | 3~5분을 시작값으로 시험. 매일 전 매뉴얼 재독 대신 변경과 오늘의 사례를 제시 |
| 오픈 준비 | 실제 준비·안전·품절·장비 확인 | 작업 후 지정 지점의 기기/인쇄물 | 의미 있는 묶음으로 확인. 중요한 점검은 필요한 시점에 직접 기록 |
| 서비스 중 | 고객 신호·팀 협력·현재 응대에 집중 | 사람, 현장 표지, 필요 시 고정 기기 | 평소 앱을 열 필요가 없도록 설계. 일반 교육/개선 요청을 끼워 넣지 않음 |
| 비긴급 예외 | 정확한 매장 정책·책임자 | 리더에게 질문, 짧은 상황 카드 | 안전한 위치에서 확인. 입력보다 응대와 담당 연결을 먼저 |
| 교대 | 미완료·품절·고장·고객과의 약속 | 구두 인계+짧은 공유 기록 | 1~2분을 시작값으로 시험. 대상·다음 행동·받는 담당·기한을 남김 |
| 마감 업무 중·퇴근 전 | 실제 마감 확인·미해결 인계·개선 한 가지 | 공용/개인 기기 | 마지막 정리 입력은 2~3분 시작값. 실제 미완료는 다음 담당에게 연결 |
| 다음 근무 준비 | 반복 문제의 원인·변경 후보 | 사장님/매니저의 넓은 화면 | 인력·재고·장비·절차·교육 중 실제 원인에 맞는 변경을 제안 |

**모든 체크를 퇴근 직전에 몰아 하지 않는다.** 실제 작업 시점이 중요한 확인과 마감 인계를 분리한다. 읽기·나중에 기록하기·실제로 수행하기를 같은 완료로 저장하면 안 된다. 향후 종이 기록을 전사할 때도 실제 수행 시각과 입력 시각을 구별해야 한다.

신입은 버디와 연습 시간을 확보하고 숙련 크루는 변경·예외만 짧게 확인한다. 동일한 교육을 전원에게 매일 반복하면 부담만 늘 수 있으므로 현장에서 확인한다.

## 4. 휴대폰·공용 기기·종이의 역할

개인 휴대폰은 일정 확인과 본인 준비에 적합하다. 매장 근무 중 개인 기기 사용이 어렵거나 원하지 않는 크루에게는 같은 일을 할 수 있는 공용 기기/브리핑 경로를 제공하는 안을 권고한다.

서비스 스테이션의 공용 태블릿은 최신 정책·인계·짧은 예외 확인에 사용한다. 식품 작업대나 고객 응대 동선과 떨어진 위치, 기기 청결·손 위생, 확인 후 현장 복귀를 함께 설계한다. 태블릿으로 바꾸는 것만으로 위생·주의 분산 문제가 해결되는 것은 아니다.

공용 기기는 크루 공통 안내와 개인 정보/관리자 편집을 분리해야 한다. 관리자 로그인 상태를 모두 공유하거나 타인의 일정·개인 기록을 무제한 노출하는 구현은 하지 않는다. 현재 본인 인증·직책 권한을 유지하며 공용 기기의 인증 전환·자동 잠금·개인 완료 귀속은 별도 설계 대상이다.

인쇄물은 빈도가 높거나 안전에 중요한 핵심 안내를 기기 없이 볼 수 있게 한다. 매장별 승인본·버전·인쇄일을 표시하고 변경 시 기존 인쇄물을 교체하는 책임자를 정하는 안이다. QR은 상세 안내로 가는 보조 수단이며 종이 안내 자체를 QR 하나로 대체하지 않는다.

현재 매뉴얼 PDF 인쇄 기능은 존재한다. 전용 상황 카드 인쇄, 버전 교체 관리, 로그인/네트워크 없이 사용할 승인된 비상 안내 묶음은 별도 후속 구현·검증이 필요하다. 기존 Flutter 웹 캐시를 오프라인 매뉴얼 보장으로 표현하지 않는다.

## 5. 긴급 상황에서 휴대폰을 봐야 하는가

| 구분 | 우선 행동 | 기기 사용의 위치 |
|---|---|---|
| 화재·심각한 신체 이상·폭력 등 즉시 안전 대응 | 상황별 사전 훈련과 현장 계획에 따른 안전 확보·도움 요청·신고 | 휴대폰은 접근 가능한 경우 통화/신고 수단. 매뉴얼 검색·AI 답변·로그인이 먼저여서는 안 됨 |
| 오주문·대기 불만·결제 오류·품절 등 서비스 예외 | 불편을 확인하고 권한 있는 담당에게 연결 | 필요하면 리더가 짧은 승인 정책을 확인. 고객 앞에서 장시간 검색하지 않음 |
| 다음에 더 잘하기 위한 방법 질문 | 버디에게 묻거나 여유 시간에 확인 | 검색·사진·짧은 시범 자료가 적합 |

같은 종류의 사건도 사람의 안전이 위협되면 첫 번째 경로로 바뀐다. 사전 매뉴얼에는 누가 리더인지, 어떻게 직접 부르는지, 매장 주소·현장 비상 안내 위치를 명확히 한다. 앱의 이상 등록은 응답이 보장된 비상 호출 시스템이 아니다.

실제 안전 자료는 해당 매장·설비·건물에 맞게 검토한다. 현재 격자 배치도의 경로 계산을 검증된 피난 경로로 사용하지 않는다. 이 문서는 처치·소화 방법을 새로 정하는 안전 매뉴얼이 아니다.

## 6. CS 매뉴얼의 보강 범위

기존 `developer/owner_starter_content.json`과 `docs/market/SOURCE.md`에 고객 맞이, 전화·예약, 주문·품절, 불만·환불, 알레르기 요청 전달이 있다. 모두 새로 만들기보다 기존 안정 ID를 보존하며 아래 관찰 가능한 기준과 연습을 보강한다. `reference` 안내를 고객 한 명마다 수행 체크하도록 바꾸지 않는다.

| CS 영역 | 매뉴얼에 넣을 구체 기준 | 연습/현장 확인 |
|---|---|---|
| 첫 인사·고객 신호 | 바로 응대하기 어려워도 고객을 인지했음을 전달하고 실제 담당에게 연결 | 주문 작업 중 입장하는 손님을 가정한 짧은 역할 연습 |
| 말투·듣기 | 확인된 사실, 필요한 양해, 다음 행동을 분명하게 말함 | 단정하거나 끊어 말하는 표현을 직접 바꿔 말해보기 |
| 서빙 동작 | 음식·그릇을 안전하게 내려놓고 위치와 주의 사항을 전달 | 실제 집기와 매장 동선으로 버디 시범·연습. 영상 자막만으로 손동작 기술을 복제하지 않음 |
| 동시 요청 | 진행 중인 응대를 유지하면서 다른 요청을 인지하고 동료에게 인계 | 계산과 다른 테이블 요청이 겹치는 사례. 안전 문제는 즉시 우선 |
| 테이블오더 지원 | 기기 사용이 어려운 고객에게 가능한 대안을 안내하고 담당이 확인 | 기기 오류/사용 질문에서 고객을 다시 기기로 돌려보내기만 하지 않는지 관찰 |
| 품절·지연 | 확인된 정보·대안·다음 안내를 제공하고 약속을 인계 | 근거 없는 완료 시각 약속을 피하는 연습 |
| 불만·교환·환불 | 듣기→사실 확인→담당/권한 확인→해결안→처리 결과 확인 | 크루가 즉시 할 수 있는 조치와 승인 필요한 조치를 매장별로 명시 |
| 마지막 주문·마감 | 입장/주문 시 이용 종료를 미리 설명하고 정중히 재안내 | 눈치 주는 청소·소등을 안내로 대체하지 않는지 확인 |
| 안전·위협·특별 요청 | 해결할 수 없는 상황을 혼자 감당하지 않고 적절한 담당에게 연결 | 모르는 정보는 확인하고, 폭언·위협에서 크루를 보호하는 경계 연습 |
| 작별·다음 근무 인계 | 감사 인사, 남은 약속·미처리 건의 담당과 다음 행동 | 해결되지 않은 문제를 완료로 체크하지 않았는지 확인 |

형식 제안: **상황 → 즉시 할 행동 → 말할 수 있는 예문 → 피할 행동 → 담당/권한 → 관찰 기준**. 크루의 읽음 확인은 숙련의 증거로 쓰지 않는다. 표정·억양·동작은 매장 시범과 연습으로 확인하고, 억양·국적·성격을 획일적인 친절 점수로 평가하지 않는다.

파트별 필요한 깊이를 다르게 한다. 모든 크루는 고객을 인지하고 적절한 담당에게 연결하는 공통 기준을 익힌다. 홀은 접객·주문·불만 대응, 주방은 품절/지연/변경의 정확한 전달, 설거지·보조는 깨끗한 식기 공급·소음·안전한 동선이 고객 경험과 어떻게 연결되는지 연습한다. 초기 대상인 신입 주방/설거지 크루에게 홀의 전체 환불 응대를 일괄 학습시키지 않는다. 고객 앞에서 정확한 정보 확인이 꼭 필요한 경우에는 확인 목적과 다음 안내를 먼저 설명하는 안을 시험한다.

### 예시 초안: 계산 중 다른 테이블에서 호출

- 상황: 한 고객의 결제를 처리하는 중 다른 고객이 도움을 요청한다.
- 행동: 현재 고객의 결제와 개인정보를 안전하게 유지하면서 새 요청을 인지했음을 알린다. 가능한 동료에게 요청을 구체적으로 넘긴다. 동료가 없으면 현재 처리 후 직접 돌아간다.
- 예문: “확인했습니다. 앞선 결제를 마친 뒤 도와드리겠습니다.” 동료에게 연결했다면 실제 담당이 받았는지 확인한다.
- 피할 행동: 아무 설명 없이 현재 고객을 두고 이동, 확인하지 않은 대기 시간 약속, 요청을 전달했다고 생각하고 잊기.
- 관찰 기준: 기존 고객에게 양해가 전달됐고 새 요청에 담당과 다음 행동이 있으며 요청이 방치되지 않는다.
- 예외: 즉시 안전 대응이 필요한 사건은 매장 비상 대응 절차를 따른다.

이 예문은 이번 검토에서 작성한 초안이며 영상 대본의 복제가 아니다. 서비스 예문과 상세 행동은 매장별로 수정·검토한다. 기존 사전 번역이 새 원문까지 검수됐다고 표시하지 않으며, 새 CS 표현은 의미와 실제 응대를 확인한 번역이 필요하다.

### 마감 일정의 중요한 구분

마지막 입장, 마지막 주문, 고객 이용 종료, 정리 작업, 크루 퇴근은 서로 다를 수 있다. 손님 이용 종료와 크루 퇴근을 같은 시각에 맞춰 놓고 정리까지 요구하면 교육만으로 해결하기 어렵다. 실제 마감 작업 시간을 근무표에 확보하고 고객 안내 시각과 연결하는 안을 검토한다. 기존 영업시간/근무표 값을 재사용하고 없는 정책 값만 명시적으로 추가해야 한다. 이번에 설정이나 일정을 변경하지 않았다.

## 7. 우선순위와 네 목적지

1. **먼저 검증:** 기존 CS 자료 5개 내외 보강, 시작 브리핑, 버디 역할 연습, 교대/마감 미해결 인계, 핵심 인쇄 안내. 새 기능 전에도 기존 앱과 종이로 현장 시험 가능.
2. **그다음 제품화:** 오늘의 변경 요약, 짧은 상황별 검색 결과, 공용 기기 사용 흐름, 승인된 핵심 안내의 오프라인 제공, 매뉴얼 버전에 연결한 개선 피드백.
3. **효과 확인 후 확장:** 사건을 개선 후보로 분류하고 다음 근무의 연습 주제를 제안하는 기능. 매장별로 검토한 개선만 적용.

업무는 시작·교대·마감과 필요한 실행 점검, 매뉴얼은 방법·CS·상황 안내, 근무표는 안정적인 인원·교육/인계 시간 확보, 우리매장은 정책·권한·개선 검토를 담당하는 안이다. 재고·발주·동선은 품절·지연·안전의 원인을 줄이는 기존 운영 범위로 유지한다.

별도 강좌·시험·교육 진도·랭킹을 우선 추가할 필요는 없다. 기존 D-099의 별도 교육 기능 제외와 CS 자료·현장 연습은 양립할 수 있다. 이번 질문만으로 LMS 전환을 확정하지 않는다. 과거 계획의 PiP·이어폰 안내는 아직 별도 실험 과제로 두며, 이번 권고는 서비스 중 상시 안내보다 사전 연습을 우선하는 것이다. 기존 확정 계획을 삭제하거나 구현 완료로 바꾸지 않는다.

## 8. 자가 발전 스킬의 적용 가능성

### 이미 있는 기반

`docs/CONTENT_IMPROVEMENT.md`, `developer/content_memory.mjs`, `scripts/content-cycle.mjs`를 확인했다. 출처·오류·수정 이유·피드백을 누적하고 다음 요청에 재사용하며, 작업 입력을 고정하고 중복 평가를 방지한다. 운영 정책은 D-101에 따라 **사용자가 요청할 때 실행**한다. 스케줄 설정 코드가 존재하는 것과 자동 실행이 승인된 것은 다르다.

로컬 개발 도구이며 인증된 현장 피드백 UI, 클라우드 공동 기억, 고객 만족 개선의 인과 평가까지 구현된 것은 아니다. 모델 가중치가 자동 학습되거나 앱 코드가 스스로 배포되는 기능도 아니다. 테스트 통과는 이 기술적 동작의 확인이며 현장 효과를 증명하지 않는다.

### 제안하는 세 가지 수준

| 수준 | 가능한 개선 | 권고 |
|---|---|---|
| 콘텐츠 개선 | 반복되는 질문·실패·불명확한 안내를 모아 매뉴얼 수정안 생성 | 기존 기반을 재사용하는 첫 단계 |
| 운영 제안 | 인력·품절·장비·인계·교육 원인을 구별하고 다음 근무의 조정 후보 제안 | 관찰 자료가 쌓인 뒤 검증. 교육만으로 원인을 덮지 않음 |
| 앱 기능/코드 개선 | 재현된 불편을 이슈·검토 가능한 변경으로 만들고 테스트 | 개발 워크플로에서 다룸. 현장 기록이 직접 코드를 수정·배포하는 방식으로 연결하지 않음 |

향후 `restaurant-service-improvement` 같은 프로젝트 전용 스킬로 반복 절차를 정리할 수 있다. 스킬은 **조사·판단·수정안 작성·검증 방법을 재사용하는 지침**이며 앱 런타임·저장소·권한·측정을 대신하지 않는다. 이번 검토에서는 스킬 파일을 설치하거나 실행 예약을 만들지 않았다.

제안 실행 순서:

1. 요청자가 범위와 문제를 지정한다. 승인된 매뉴얼 버전과 정제한 현장 관찰을 입력으로 고정한다.
2. 현상과 원인을 구별한다. 예를 들어 ‘불친절’ 신고를 곧바로 크루 태도 문제로 확정하지 않고 인원·품절·동시 요청·권한을 확인한다.
3. 근거·적용 조건을 확인하고 기존 문서의 중복·충돌을 조사한다.
4. 변경 전/후, 이유, 영향받는 역할·매뉴얼·인쇄물·번역을 제시한다. 매장 고유 정책과 일반 권고를 구분한다.
5. 문장/현장 적합성/안전/권한을 검토하고 짧은 역할 연습으로 확인한다.
6. 기존 D-111에 따라 사장님이 변경 내용을 보고 TAP별로 선택 적용한다. 적용자·버전·시점과 되돌릴 원본을 남긴다.
7. 다음 근무에서 실제 도움이 됐는지 측정해 유지·수정·철회한다. 평가가 없으면 미측정으로 남긴다.

운영자 요청으로 초안을 만드는 부분부터 적용하는 편이 현재 결정과 일치한다. 주기 실행은 별도 선택 대상이고, 이전 릴리스의 일회성 검토 생략을 향후 자동 발행 권한으로 재사용하지 않는다. 고객 대화·음성·영상 상시 수집이나 개인별 자동 인사평가를 전제로 하지 않는다. 공용 지식으로 승격하기 전 매장/사람 식별 정보와 민감한 사건 정보를 제거하고 재사용 범위를 검토해야 한다.

### 후속 데이터 경계 제안 — 미구현

- 관찰 기록: 매장 범위, 영업일/교대, 상황 유형, 관련 매뉴얼 ID/버전, 사실·조치·남은 일. 만족도를 기록 수만으로 추정하지 않는다.
- 개선 후보: 기준 버전, 수정 전/후, 출처·이유, 위험/적용 조건, 검토 상태, 적용 시점, 결과와 되돌림 연결.
- 브리핑: 승인된 기존 문서의 참조와 오늘의 변경을 묶는다. 별도 매뉴얼 원본을 복제하지 않는다.
- 기존 `workIssue`는 수행 불가/주의의 업무 계약을 유지한다. 고객 상황 피드백과 1:1로 같다고 가정하지 않고 최소 필드 연결 또는 별도 기록의 필요를 검토한다.
- 파트는 분류, 직책은 권한이다. 매장 격리, revision 확인, 이미 생성된 업무·완료 기록 보존을 유지한다. 한국 영업일/자정 넘는 교대를 고려한다.
- 향후 오프라인 승인 안내는 매장·언어·버전·검토 시점·원문 해시를 묶고 최신 확인 상태를 표시한다. 로그인 실패/통신 장애/오래된 안내/권한 회수 정책은 별도 검증한다.

## 9. 실제 방향성 검증 계획 — 제안

소규모 식당 2~3곳에서 4주를 시작안으로 제안한다. 1주 기준선, 2주 적용, 1주 재확인이다. 실제 참여 매장·기간은 미확정이다. 비교 가능한 요일·피크/비피크·근무 인원·손님 수·신입 비중을 기록한다. 가능하면 매장/교대별 시작 시점을 달리해 계절·프로모션·숙련 변화 영향을 살핀다. 작은 전후 비교는 확정적 인과 증명이 아니다.

첫 시험은 새로운 앱 기능 없이 기존 CS 문서 5개, 인쇄 카드, 시작 브리핑, 버디 연습, 짧은 인계로 구성할 수 있다. 직원은 근무시간 안에서 참여하고 면담과 관찰의 목적을 알고 참여하도록 운영한다.

| 측정할 것 | 측정 방식 | 해석 주의 |
|---|---|---|
| 고객 응대 | 같은 문항의 짧은 응대 만족 조사와 응답 수/비율 | 음식·가격 만족과 구분. 응답자 편향과 소수 표본을 표시 |
| 반복 서비스 문제 | 주문 100건당 확인된 동일 유형 불만·오주문·누락 | 주문 수와 신고 수를 함께 기록. POS 연결은 현재 구현으로 가정하지 않음 |
| 현장 행동 | 표본 시간대의 인지/양해/담당 연결 등 관찰 기준 충족 | 열람·퀴즈·체크 수와 구분. 통제되지 않은 관찰 효과를 고려 |
| 인계 | 다음 교대에서 재발견한 미해결 누락, 담당 없는 건 | 문제 신고가 늘어도 초기에 발견이 늘어난 것일 수 있음 |
| 크루 부담 | 서비스 중 앱 접촉 횟수/시간, 마감 입력 시간, 도움 요청 용이성 | 전체 폰 활동 상시 추적 대신 짧은 표본 관찰·자기 보고 우선 |
| 매니저 부담 | 반복 설명 시간과 개선 검토 시간 | 한쪽 시간을 줄이고 다른 쪽을 크게 늘리지 않는지 확인 |

채택 조건은 **응대/인계 지표의 개선과 서비스 중 기기 사용·업무 부담의 비악화가 함께 관찰되는 것**이다. 구체적인 수치 목표는 기준선을 본 뒤 고정한다. 만족도 상승·불만 감소 퍼센트를 지금 약속하지 않는다. 안전 문제가 생기거나 입력 때문에 고객 응대가 지연되면 해당 흐름을 줄이거나 중단해 검토한다. 앱 사용 증가만으로는 성공 처리하지 않는다.
