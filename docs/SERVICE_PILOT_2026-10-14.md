# 근무 흐름·CS 현장 검증 실행표

2026-10-14 사용자 계획 진행 요청에 따른 실행 준비 자료. 참여 매장·크루·고객이나 측정 결과는 아직 없다. 앱 구현/테스트와 현장 효과를 구별한다.

## 시작 구성

소규모 식당 2~3곳, 4주를 시작안으로 사용한다. 1주 기존 방식 측정, 2주 적용, 1주 재확인이다. 운영자가 실제 참여·관찰 시간과 자료 이용 범위를 정한 뒤 실행한다. 비교 가능한 요일·피크/비피크·근무 인원·손님 수·신입 비중을 남긴다. 한 번의 작은 전후 비교를 인과 효과 확정으로 보고하지 않는다.

근무시간 내 3~5분 시작 브리핑, CS 상황 1개 버디 시범/연습, 필요한 시점의 실제 점검, 교대/마감 짧은 인계를 시험한다. 실제 신규 크루 교육이나 오픈/마감 작업 시간을 이 분량으로 제한하지 않는다.

앱에서는 업무 → 근무 준비·인계를 연다. 시작 화면은 리더가 최대3개 등록 매뉴얼과 변경 안내를 선택한다. 안내 확인은 읽음으로만 기록된다. CS·개선 화면에서 사장님은 원문을 검토해 CS 초안을 등록하고 매뉴얼에서 매장 규칙·예문·번역을 보완한다. 크루의 연습 뒤 지정 버디가 자기 계정으로 별도 확인한다.

교대·마감 화면은 대상·사실·다음 행동·받는 담당을 기록한다. 담당이 없으면 미정으로 명시한다. 다음 행동에 필요한 시점을 적고 현장에서 서로 되짚어 확인한다. 미해결 인계는 다음 영업일에도 남으며 담당이나 권한 있는 리더가 실제 조치 결과를 기록한다. 이 기록은 기존 업무 완료와 별개다.

PDF/인쇄는 사장님이 검토해 등록한 매뉴얼로 만든다. 현재 인쇄물의 버전·생성일을 확인하고 교체 담당자를 정한다. 다운로드한 PDF는 기기 밖에서 볼 수 있지만 앱 자체의 오프라인 저장/동기화나 로그인 없는 비상 안내를 보장하지 않는다. 공용 기기를 사용하는 경우 현재 개인 인증을 유지하며 관리자 계정으로 다른 크루의 확인을 대신 기록하지 않는다.

## 측정할 항목

| 항목 | 기록 | 주의 |
|---|---|---|
| 응대 만족 | 같은 질문의 응답 수·분포와 응답률 | 음식·가격 만족과 구분. 개인정보 없이 집계 |
| 반복 문제 | 확인된 동일 유형 불만·오주문·누락과 해당 기간 주문 수 | `문제수 / 주문수 × 100`; 앱에 POS 연결이 있다고 가정하지 않음 |
| 현장 행동 | 고객 인지·양해·담당 연결 기준을 관찰한 기회 수와 충족 수 | 읽음·체크와 구분. 상시 녹음/영상 수집을 전제로 하지 않음 |
| 인계 | 다음 교대에서 재발견한 누락과 담당 미정 건 | 신고가 늘었다고 곧바로 서비스 악화로 해석하지 않음 |
| 크루 부담 | 표본 시간의 서비스 중 앱 접촉, 입력 소요, 도움 요청의 어려움 | 개인 휴대폰 전체 활동 추적 대신 관찰·자기 보고 |
| 리더 부담 | 반복 설명 및 개선 검토 시간 | 한쪽 부담을 줄이고 다른 쪽을 늘리지 않는지 확인 |

기록 최소 열: 매장 익명 코드, 날짜/교대, 적용 단계, 피크 여부, 근무 인원, 주문 수, 문제 유형별 건수, 관찰 기회/충족 수, 만족 응답 수/분포, 표본 앱 접촉/입력 시간, 인계 누락, 근거 버전, 측정자 메모. 사람·고객 식별 정보를 넣지 않는다. 미수집 값은 빈칸/미측정으로 남기며 0으로 채우지 않는다.

## 개선 작업

CS·개선에 실제 사실과 결과를 기록하고 원인을 아직 모름/인원·배정/재고·품절/설비·도구/인계·소통/방법·정책·교육으로 구분한다. 의견은 작성자와 매뉴얼 편집 권한이 있는 리더에게만 표시된다. 도움 됨·보완 필요는 관찰자의 평가이지 객관적 고객 만족 수치가 아니다.

요청한 개선 검토는 [.agents/skills/restaurant-service-improvement/SKILL.md](../.agents/skills/restaurant-service-improvement/SKILL.md)를 사용한다. 식별 정보를 정제한 관찰과 당시 매뉴얼 버전으로 수정안을 만들고, 사장님이 확인해 선택 적용한 뒤 다음 근무에서 재확인한다. 기록 입력 자체가 AI 호출·예약 실행·공용 발행을 만들지 않는다.

채택 기준: 응대/인계가 나아지고 서비스 중 기기 접촉과 업무 부담이 악화되지 않는지 함께 확인한다. 수치 목표는 기준선 후 적용 전에 고정한다. 고객 응대 지연·안전 문제가 생기면 해당 입력/안내 흐름을 줄이거나 중단해 원인을 검토한다. 실제 효과가 확인된 수정만 유지하고 근거 버전·관찰을 남긴다.
