# 시간대·근무·공동 업무 담당 계약

2026-09-30 · D-063. 사용자 선택: 시간대 중복 허용 및 필요 인원 합산, 공동 완료, 시간대별 별도 수행, 같은 파트의 지원 완료, 누구나=그날 근무 크루, 유효 근무 구간에 따른 자동 인계.

## 정보 흐름

`영업시간의 시간대 ID + 파트 ID → 반복 크루 배정 → 날짜별 유효 근무 → TAP/Task 담당 표시`

시간대 이름은 표시용이며 연결은 고유 ID를 쓴다. 같은 크루의 겹치는 실제 근무를 두 자리 인원으로 계산하지 않는다. 기존 오픈/준비/피크/브레이크/마감 분류는 실제 시각을 가진 시간대에 임의 연결하지 않는다.

## 업무 설정

TAP `settings.assignment`와 Task `settings.assignment`는 같은 구조를 사용한다.

| mode | 의미 |
|---|---|
| legacy | 기존 파트/역할 규칙. 이전 데이터의 호환 기본값 |
| scheduled | `timeBandIds`의 시간대와 `partId`를 통해 실제 근무자를 산출 |
| crew | `crewIds`로 지정한 활성 크루의 공동 업무 |
| anyone | 해당 날짜의 유효 근무가 있는 활성 크루의 공동 업무 |
| inherit | Task에서만 사용. TAP의 담당 설정을 따름 |

시간대마다 별도 실행을 만들고 크루 수만큼 업무를 복제하지 않는다. Task가 특정 시간대를 별도 지정하면 그 시간대의 실행에 포함한다. 같은 시간대에서 한 명이 완료하면 공동 업무는 완료된다. 다음 시간대의 실행은 별도로 남는다.

TAP 설정과 시간대의 `연결 업무`는 같은 설정 화면 및 `save_tap_settings`를 사용한다. 시간대를 편집한 초안은 먼저 저장한 뒤 업무 연결을 연다. 서로 독립된 연결 목록을 중복 저장하지 않는다. 매뉴얼 전용 판매 메뉴와 자동 재고·주문 업무를 반복 업무로 임의 변환하지 않는다.

## 담당과 권한의 구분

- 담당 표시는 가능한 크루 목록이 아닌 실제 근무 구간이다. 크루 이름과 고정 색상에 필요 시 구간을 함께 표시한다.
- `내 담당만`은 담당 여부로 필터링한다. 지원 완료 권한이 있다고 내 담당으로 표시하지 않는다.
- scheduled 업무는 같은 파트에서 근무 가능한 크루도 지원 완료할 수 있다. 직책의 완료 제한은 유지한다.
- anyone은 파트 미선택과 다른 의미이며 그날 유효 근무가 있어야 한다.
- 실제 담당이 없으면 `담당 미배정`을 보여준다. 자동으로 누구나 업무로 변경하지 않는다.
- 사장님·매니저의 관리 권한과 서버 직책 제한을 유지한다. 화면의 배지나 client 입력으로 권한을 결정하지 않는다.

## 변경과 기록

휴무·단축·부분 OFF 신청 중에는 원래 근무를 유지한다. 사장님 승인 후 유효 근무를 바꾸며 대타 배정은 빈 구간과 연결한다. 미완료 업무는 최신 유효 근무로 담당을 다시 계산한다. 완료 업무는 담당 스냅샷과 실제 완료자를 유지한다.

반복 배정 재적용은 선택 기간의 해당 반복 배정에 한정하며 승인된 예외·대타·출퇴근·이미 시작한 근무를 보존한다. 재적용으로 휴가 구간을 다시 근무로 만들거나 대타를 중복 생성하지 않는다.

자정을 넘는 근무와 시간대는 날짜를 포함한 구간으로 비교한다. 담당 구간은 시간대와 근무의 교집합이다. 사람이 두 시간대에 걸쳐 보이는 것과 같은 사람이 두 인원으로 집계되는 것은 구분한다.

## 저장·UI·검증

기존 JSON 영역 저장과 revision 검증을 사용하며 별도 번역 이름 기반 테이블이나 화면별 HTTP 저장을 추가하지 않는다. 저장 실패는 초안을 보존한다. 같은 화면군은 [UI/UX 가이드](UI_UX_GUIDELINES.md)의 제목·폼 간격·하단 저장·반응형 규칙을 적용한다.

검증 결과와 배포 여부는 `project-state.json`의 최신 구현/검증 이력과 [앱 UI/UX 점검](UI_UX_AUDIT_2026-09-30.md)에 기록한다. 이 문서의 계약만으로 실제 운영 데이터 이관·네이티브 검증 완료를 뜻하지 않는다.
